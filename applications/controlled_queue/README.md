# Controlled queue preprocessing

Status: **MODEL/PREPROCESSING ONLY**

This directory freezes and compiles the deterministic model inputs for the
24-state, two-action controlled-queue benchmark. It does not contain a sampled
trace, a statistical certificate, a theorem-produced good path, or a proof of
unknown-kernel target-policy OPE.

## Files

- `model-v1.json`: exact input schema and benchmark parameters. Rational values
  are canonical strings such as `3/4`; JSON floats are forbidden.
- `generated/model-v1-tables.json`: full exact rational candidate-kernel,
  policy, fixed-predictor, control-cost, outcome, and Brier-loss tables.
- `generated/model-v1-manifest.json`: schema/model/generator identifiers,
  frozen future parameters, and SHA-256 bindings for the input and outputs.
- `../../FormalSLT/Applications/ControlledQueueData.lean`: generated Lean
  definitions and tables. It intentionally contains no theorem or certificate.

The generator is `../../scripts/generate_controlled_queue_model.py` and uses
only the Python standard library.

## Regenerate and verify

```bash
make generate-controlled-queue-model
~/.elan/bin/lake exe cache get
make verify-controlled-queue-model
```

The verification target fails if any generated byte or manifest hash is stale,
runs the narrow arithmetic/schema test suite, and compiles only the generated
Lean data module. The larger application remains open until later slices add a
trace, causal prediction updates, theorem bridges, exact Lean certificate
checks, and matched numerical comparisons. The frozen v1 schema records that
the next trace slice must add an initial state, language-independent PRNG and
sampling contracts, and exact prior/posterior/candidate/coordinate/tilt weight
tables; none of those trace semantics are implemented here.
