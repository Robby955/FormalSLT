# FormalSLT overview film

This directory contains the fact-bound source for a caption-led overview of
FormalSLT: reusable Lean proof infrastructure for statistical guarantees. The
72-second main cut opens on the failure of fixed-time reasoning under repeated
monitoring, then moves from checked anytime-valid control to the current theorem
range across VC theory, Rademacher complexity, chaining, PAC-Bayes, sequential
inference, and dependent data. The controlled queue appears later as one worked
case study, not as the scope of the project. A native 4:5 13-second cut carries
the same result-first framing for social previews.

The checked facts are extracted from the exact merged-main commit
`501fee458a539db654097dbec8933427dae9fee9`. The extractor fails if that commit
does not contain the named VC, metric-entropy, chaining, PAC-Bayes, e-process,
trajectory, supplied-Poisson stationary-risk, and controlled-queue
declarations with the expected statement shapes. It also checks the queue
cardinalities, hit-probability formula, and exact row-TV transfer anchor.

## Render

Requirements:

- Python 3.13
- Manim Community 0.20.1
- FFmpeg
- a LaTeX installation plus `dvisvgm` for theorem-faithful `MathTex` equations
- the Avenir Next and Menlo fonts included with macOS

Each scene starts at a reviewed time listed in `MAIN_SCENE_STARTS` and
`SOCIAL_SCENE_STARTS`. The scene checks its own start against the renderer
clock and holds its finished composition until the next boundary. Every composition also
runs frame, content-band, and pairwise overlap assertions before it animates;
a layout that collides fails the render instead of shipping.

The bound shapes burned into the classical, PAC-Bayes, anytime, and queue
scenes are copied from the pinned declarations. The closing ledger shows four
representative theorem families and points to the exact declaration names and
files in `facts.json`.

The mathematical inputs and scene timing are fact-bound and deterministic.
The rendered pixels are not promised to be bit-identical across platforms:
Avenir Next and Menlo are macOS system fonts, and the Python requirements do
not lock the operating system or every transitive renderer component. The
official render receipt records the renderer environment and output hashes.
Use that environment when reproducing release pixels.

Install the renderer into an isolated environment with:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r media/formalslt-overview/requirements.txt
```

From the repository root:

```bash
./media/formalslt-overview/render.sh proof
./media/formalslt-overview/render.sh social-proof
./media/formalslt-overview/render.sh final
./media/formalslt-overview/render.sh social
./media/formalslt-overview/render.sh poster
./media/formalslt-overview/render.sh release
```

`proof` renders a fast 854 by 480 review copy; `social-proof` renders a native
432 by 540 review copy. `final` renders the 1920 by 1080 master and `social`
renders the separately composed 1080 by 1350 4:5 master. `poster` renders the stable
click-to-play image independently of film timing. `release` refreshes both mobile
H.264 cuts, the poster, and `render-receipt.json`. It
builds and validates that complete set in a temporary directory before
replacing the public files; a failed encode, metadata check, or
promotion restores the prior set. Intermediate movies are under
`media/formalslt-overview/out/` and are intentionally ignored by Git.

Explanatory text is burned into the frames; the main cut also ships with a
WebVTT track and a searchable transcript.

## Sound

The films use the original deterministic score generated by
`compose_soundtrack.py`. It uses no recordings, samples, or third-party audio.
The score is built from five finite harmonic swells and three restrained
mid-register accents in the main cut, with deliberate negative space and no
sub-bass pulse. Delivery applies an 80 Hz high-pass and EBU R128 normalization;
the receipt rejects the final AAC if its loudness, range, peak, channel count,
or sample rate leaves the reviewed bounds. Every explanation remains written
on screen, the main cut ships a WebVTT caption track, and `TRANSCRIPT.md`
carries the same content for search and screen readers.

The committed `facts.json` is a reviewable mathematical receipt. Every render
regenerates it from the bound Git commit and stops if a required declaration,
statement shape, cardinality, formula, or scope identity no longer matches.
`render-receipt.json` separately records source and asset hashes, video
codecs, durations, and renderer versions.

## Public delivery

- The repository poster opens the responsive Pages player for the current film.
- The main cut, short cut, poster, and captions live in `delivery/` so a film
  release remains independent of documentation-site generation.
- The receipt records the film's fact-bound commit separately from the later
  commit that publishes the delivery files.
- `TRANSCRIPT.md`, the WebVTT track, source, facts, and render receipt stay in
  the repository.
- A tagged release may attach the lossless archival master later; the committed
  MP4 files are delivery encodes, not the archival boundary.
