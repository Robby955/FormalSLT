Reader route · Lean

Import a topic, then narrow to a theorem.

The candidate v0.2 API is organized around four topic umbrellas. They are the supported discovery surface; individual implementation modules remain available when a downstream proof needs a smaller import.

Topic imports

  • import FormalSLT.PACBayes

    PAC-Bayes change of measure, empirical-Bernstein bounds, and posterior-risk endpoints.

  • import FormalSLT.Sequential

    Sequential processes, filtrations, conditional means, and anytime-valid components.

  • import FormalSLT.StochasticDynamics

    History-dependent trajectories, Markov risk, Poisson corrections, and empirical kernels.

  • import FormalSLT.VC

    VC dimension, growth functions, and finite-class learning bounds.

Reuse discipline

  • Start from the fully qualified declaration shown in doc-gen. Long names are deliberate: they carry the scope and mechanism.
  • Check the theorem’s type before relying on prose. Finiteness, measurability, adaptation, boundedness, and positivity premises remain explicit arguments or typeclass assumptions.
  • Use the stable-import examples as executable API receipts for the four umbrellas.
  • For flagship endpoints, inspect the associated #print axioms receipt. The intended public profile is [propext, Classical.choice, Quot.sound].

Candidate API means reviewable, not immutable. The release tag and API stability policy govern compatibility. A green documentation build does not create a release by itself.
