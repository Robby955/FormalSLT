## Intended release scope

- The four topic imports and 19 declarations in the
  [candidate API policy](../api-stability.md).
- All-sample-size IID empirical-Bernstein PAC-Bayes, adaptive trajectory
  inference, and stationary Poisson and unknown-kernel certification.
- The opt-in 20-state random-refresh load
  [application](../random-refresh-load-application.md).
- Exact v0.1 example replay, downstream installation checks, declaration and
  axiom snapshots, theorem discovery, and literature/provenance documentation.

## Known boundaries

- The IID empirical-Bernstein endpoint is offline, not an optional-stopping
  theorem.
- Trajectory selection ranges over predictors and tilt atoms declared before
  scoring; it does not authorize post-outcome construction of new candidates.
- The named deterministic application path is not proved to belong to the
  theorem-produced good event, so that application step remains conditional.
- Normalized empirical-kernel radii require positive limiting row frequencies;
  candidate-kernel budget convergence additionally requires empirical
  discrepancy convergence.
- Application declarations are not part of the 19-name compatibility promise.
- Full continuous Dudley, all-real predictable tilt optimization, and
  continuous-state stationary Poisson certification remain open. See the
  [scope ledger](../assumptions-and-nonclaims.md).

## Publication gate

Before calling v0.2.0 released:

1. Merge the reviewed candidate and record the resulting exact commit and tree.
2. Pass the complete [release audit](../public-release-checklist.md) on that
   exact commit, including hosted Linux and macOS downstream jobs.
3. Create `v0.2.0`, then run the manual **Release tag install smoke** workflow
   on both operating systems. The script fails if the remote tag is missing or
   if Lake installs any commit other than the tag target.
4. Create an actual GitHub Release for that tag with the exact-SHA receipt and
   these known boundaries.
5. Archive the tagged artifact, mint the DOI, update `CITATION.cff`, and verify
   the DOI resolves to the same version and source.
6. Deploy the generated documentation and verify that source links are pinned
   to the released revision.

Only after steps 1--6 pass is this installation declaration valid:

```lean
require «formal-slt» from git
  "https://github.com/Robby955/FormalSLT.git" @ "v0.2.0"
```

Until then, use an exact reviewed commit as described in the
[README](../../README.md), and cite the current unversioned
[`CITATION.cff`](../../CITATION.cff) without claiming a v0.2 DOI.
