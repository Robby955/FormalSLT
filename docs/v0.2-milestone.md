# v0.2 Milestone Definition

Status: planning document. Nothing here is a public claim until the named
theorems compile and the release checklist passes.

v0.1 froze a finite-class theorem spine with two checked endpoints (the
finite-class Hoeffding confidence sequence and the unit-interval finite-net
Dudley bridge). The roadmap in `README.md` is a flat checklist and does not
say which subset constitutes the next release. This document fixes that.

## Headline goal

**v0.2 removes exactly one boundary from the v0.1 nonclaims list: the finite
hypothesis class on the PAC-Bayes gate.**

The release centerpiece is the derived continuous-posterior PAC-Bayes track
(Route B), ending in a kernel-checked, nonvacuous numeric certificate for a
Gaussian posterior/prior pair. Design and staging:
`docs/route-b-continuous-pac-bayes-blueprint-2026-06-10.md`.

## Stretch (in v0.2 if ready, never blocking)

- Heterogeneous sharp McDiarmid: different law per coordinate, via the
  existing exposure-martingale route. Closes the second-most-cited nonclaim.
- Compiler `gaussian` spec kind (Route B step B5): only after B4 is checked.
- First Mathlib upstream PR: the `Measure.pi` KL-additivity lemma from B4a is
  the strongest candidate (general, Mathlib-shaped, used in anger here).

## Explicitly out of scope for v0.2

Unchanged from the v0.1 nonclaims unless listed above:

- continuous Dudley entropy-integral theorem (stays in the
  `docs/next-lane.md` lane; needs the measurable-supremum layer);
- all-real-`λ` PAC-Bayes optimization (the B2 gate is fixed-`λ`);
- measure-theoretic iid sample lift (the data side stays finite in B2);
- e-process / optional-stopping confidence sequences;
- any trained-model or neural-network generalization claim. The Gaussian
  certificate certifies one posterior/prior pair at explicit numerics, not a
  model trained on data.

## Release criteria

All of the following, in addition to the standing audit commands in
`README.md`:

1. every in-scope theorem compiles in `lake build FormalSLT` with zero
   `sorry`, zero `admit`, no custom axioms;
2. `#print axioms` for every new public theorem stays inside
   `[propext, Classical.choice, Quot.sound]`;
3. the blueprint doc is updated to match any signature that moved, in the
   same PR that moved it;
4. `python3 -m pytest compiler/` passes, including the generated-cert
   golden-file sync test;
5. proof-frontier manifest and doc anchors pass `--check`;
6. README counts refreshed by rerunning the count commands; nonclaims list
   updated to remove exactly the boundary that was closed and nothing else;
7. `docs/comparison-table.md` updated honestly: the continuous-posterior
   gate is a first for the Lean PAC-Bayes libraries surveyed there, and the
   caveats column must say what the data side still assumes;
8. tag `v0.2.0-rc1` per `docs/release-and-submission-strategy.md`, then run
   `docs/public-release-checklist.md` before any public announcement.

## Sequencing and review

One step per PR in blueprint order (B1 -> B2 -> B3 -> B4a -> B4b), each
reviewed against the lane doc's target signature before merge. Stretch items
ride in parallel branches and merge only when green. If B4a stalls on the
Gaussian integral work, v0.2 can ship B1-B3 plus the finite-side Gaussian
closed forms with the certificate deferred to v0.2.1; in that case the
headline claim must be reduced accordingly (derived continuous gate, no
numeric certificate).
